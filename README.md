# Спецификация проекта: Веб-сервис прогнозирования страхования

**Основная цель:** Разработка веб-сайта, который позволяет пользователю вводить данные через форму и получать вероятность получения страхования транспортного средства.

---

## 1. Функциональные требования
* **Ввод данных:** Удобная веб-форма для сбора параметров (возраст, пол, тип автомобиля, страховой стаж и т.д. на основе анализа данных датасета Kaggle).
* **Обработка данных:** Бэкенд должен принимать данные, валидировать их и передавать в ML-модель.
* **Вывод результата:** Сервис должен возвращать понятный результат: вероятность получения страховки или ответ (вам доступно или недоступно страхование).
* **Обработка ошибок:** Корректная обработка неверного ввода пользователя или сбоев на стороне сервера.

## 2. Предлагаемый технологический стек
* **ML/DS:** Python (Pandas, Scikit-learn, XGBoost/CatBoost, Optuna, AutoML).
* **Backend:** Python (FastAPI, Pydantic).
* **Frontend:** Честно говоря не знаю что там модное сейчас есть во фронте, какой-нибудь React например.
* **Инфраструктура:** Docker, VPS.
* **Источник данных:** [Kaggle Playground Series S4E7](https://kaggle.com/competitions/playground-series-s4e7/data?select=train.csv).

---

## 3. Структура декомпозиции работ
**Это не роли, а зоны ответственности в проекте, вероятно мы все же не разделимся жестко по ролям, а будем тесно сотрудничать**

### Блок 1: ML/DS
- **EDA (Исследовательский анализ данных):** Анализ корреляций, обработка пропусков и визуализация распределений в данных.
- **Pipeline предобработки:** Кодирование (One-Hot/Label), масштабирование и генерация признаков (feature engineering).
- **Разработка моделей:** Обучение моделей и подбор гиперпараметров.
- **Оценка качества:** Валидация моделей с использованием подходящих метрик (Бинарная классификация).
- **Сервис инференса:** Отдельный сервис-контейнер для инференса обученной модели (FastAPI).

### Блок 2: Backend
- **Архитектура API:** Проектирование RESTful эндпоинтов (например, `POST /predict`).
- **Интеграция модели:** Связь с сервисом инференса модели.
- **Валидация данных:** Использование схем Pydantic для валидации входящих данных.
- **Документация API:** Документация Swagger/OpenAPI для Frontend.

### Блок 3: Frontend
- **UI/UX Дизайн:** Создание формы и экрана вывода результата.
- **Реализация формы:** Создание динамической формы с подходящими типами ввода (слайдеры, выпадающие списки, переключатели). Предусмотреть валидацию ввода во фронте.
- **Интеграция с API:** Связка фронтенда с бэкендом FastAPI через `fetch` или `axios`.
- **Визуализация данных:** Нужен красивый и понятный способ отображения полученного прогноза.

### Блок 4: DevOps
- **Контейнеризация:** Создание `Dockerfile` для бэкенда и фронтенда; оркестрация приложения.
- **Настройка сервера:** Подготовка VPS и обеспечение базовой безопасности.
- **Деплой и веб-сервер:** Деплой сервиса на VPS.

### Блок 5: Архитектура и организация
- **Репозиторий:** README, `.gitignore`, документация
- Фиксация JSON-контракта между ML, Backend и Frontend
- Финальная сборка всех модулей воедино и тестирование end-to-end
- Уточнение требований у преподавателя

---

## 4. Этапы проекта
1. **Этап 1: Исследование и прототип** - EDA завершен, создан сервис инференса модели, возвращающий прогнозы, модель при этом может быть заглушкой.
2. **Этап 2: Основная интеграция** - Интеграция сервиса инференса с бэкендом, фронтэндом, работоспособное приложение с формой ввода данных и получения прогнозов.
3. **Этап 3: Деплой** - Весь стек запущен в Docker на удаленном VPS.
4. **Этап 4: Финальная доработка** - Улучшение UI/UX, исправление багов и подготовка к финальной презентации, рефакторинг. Здесь можно добавлять что то ещё, если есть желание.
